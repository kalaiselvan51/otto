Claude Token Playbook

How to get more out of Claude while spending less of your limit. Told three ways: for a newcomer, from a friend, and for a developer. Every tip carries a quote and a link to the page that backs it.

The one thing to understand first

Claude has no memory between messages. Each time you hit send, the whole conversation is sent again and read again. A long chat makes every new message expensive, even a one-liner.

Every previous message is resent on every turn, so a session that has wandered through three unrelated problems pays for all three on each new message. Help Center

New to Claude

Claude counts everything in tokens: small pieces of text. 200,000 tokens is about 500 pages. Your plan gives you a token allowance, and everything Claude reads or writes uses some of it. These twelve habits make that allowance last.

  • Know your two meters

    Paid plans have a limit that resets every five hours and another that resets weekly. Chat, the desktop app and Claude Code all draw from the same pot. See what is left in Settings → Usage.

    Paid plans have two types of usage limits: a session limit that resets every five hours, and weekly limits that reset once every week. Help Center

  • New topic, new chat

    Done with one subject? Open a fresh chat. Otherwise Claude keeps re-reading the old one with every message.

    Begin fresh chats for new topics to minimize the size of your context window. Help Center

  • Ask everything in one message

    Three related questions in one message cost less than three separate messages, because the conversation is only re-read once.

    If you have multiple related tasks or questions, group them in a single message. Help Center

  • Say exactly what you want

    Include the goal, who it is for, the format and the length. A clear first message saves the follow-ups that fix a vague one.

    Think of Claude as a brilliant but new employee who lacks context on your norms and workflows. The more precisely you explain what you want, the better the result. Prompting guide

  • Document first, question last

    When you paste something long, put it at the top and your question underneath.

    Queries at the end can improve response quality by up to 30 percent in tests Prompting guide

  • Put files you reuse in a Project

    Upload a file to a Project once instead of attaching it to every chat. Reused Project content is cached and counts less. Free accounts get five Projects.

    Content in projects is cached and counts less against your limits when reused. Help Center

  • Use the lightest model that does the job

    Click the model name to switch. Haiku is the cheapest and fastest, Sonnet handles most things, Opus and Fable are for hard problems and use your limit faster.

    Use our most efficient Haiku model, or the most recent Sonnet model for most tasks. Help Center

  • Turn the effort dial down for easy tasks

    Effort controls how hard Claude thinks before answering. Simple questions do not need it high.

    Low and Medium work well for routine tasks and stretch your usage further. Help Center

  • Switch off what you are not using

    Web search, connected apps and Research all add tokens. Turn them off for chats that do not need them. Research in particular reads many sources per question.

    Tools and connectors are token-intensive Help Center · research sessions can use up your limits faster Help Center

  • Go easy on big PDFs and images

    Claude reads each PDF page as text plus a picture of the page. Upload only the pages you need, or paste the text.

    Each page typically uses 1,500–3,000 tokens depending on content density. API docs

  • Tell Claude once, not every time

    Put standing preferences in Settings → Your Claude. Say “remember this” for facts you want kept. Memory is on by default, including on Free.

    Any instructions you add here will be applied to all of your conversations with Claude. Help Center

  • Ask for a short answer when that is all you need

    Writing costs more than reading. “Answer in two sentences” or “just the command” is a real saving.

    Telling Claude when you only need a quick answer, not a file or finished deliverable. Help Center

Day to day

From a friend who uses it all day

Okay, real talk. Almost all of it comes down to two things: keep the conversation short, and stop fiddling with settings halfway through a task. Here is what that looks like in practice.

In the app

  • Do not make Fable your daily driver

    It is the smartest one and it eats your limit fastest. On Pro it is not even in the plan, you pay extra. Opus 5.5 or Sonnet 5.5 for normal days, Fable when you are properly stuck.

    They draw from your plan's regular weekly usage limits and use them faster than other Claude models. Help Center

  • Coming back after a break costs extra

    That nice Project discount wears off when you leave. Batch your questions about a document into one sitting.

    If you come back to a project after a long break, your first message counts that content in full again. Help Center

  • Pasting a link is not free

    Claude pulls in the whole page, not the paragraph you care about. Paste the paragraph.

    the entire article is retrieved into Claude's context window. This can consume a significant portion of your usage limit Help Center

  • Save the heavy stuff for a fresh window

    Big file builds, Research runs, long agent tasks: start them when your five-hour window has just reset, not when you are at 80%.

    plan intensive work sessions around your five-hour usage windows. Help Center

In Claude Code

  • /clear is free. /compact is not.

    Switching tasks? /clear. Only compact when you need the history to carry on. Run /rename first if you might want the old session back with /resume.

    /compact reads the conversation it summarizes, so compacting a large context is itself a large request. When you want a fresh start instead of continuity, /clear costs nothing Claude Code docs

  • Pick model and effort once, at the start

    Changing model mid-session throws away the discount on everything Claude has already read. Same when you flip fast mode on or off.

    Switching with /model means the next request reads the entire conversation history with no cache hits, even though the content is identical. Claude Code docs

  • Lunch breaks have a price

    The discount on re-read history expires after an hour on a subscription, and after five minutes on an API key or once you are on paid credits. Finish the thought before you leave, or /clear when you return.

    your first message after a break longer than the cache lifetime misses the cache and reprocesses your full context Claude Code docs

  • Wrong turn? Rewind, do not compact

    Press Esc to stop it the moment it drifts. Esc Esc opens rewind, which drops the bad detour and lands you back on history that is still discounted.

    Rewinding truncates back to a prefix that is already cached, rather than building a new one as compaction does. Claude Code docs

  • Two strikes, then start over

    If you have corrected it twice and it is still wrong, a third correction just makes the chat longer. Clear and write the prompt you now know you needed.

    after two failed corrections run /clear and write a better prompt instead of a third. Claude Code docs

  • Ask it where the tokens went

    /usage shows which skills, subagents and MCP servers are eating your plan and suggests fixes; press f to apply the ones it can. /context shows what is filling the window right now.

    Example row from the docs: 25% Trim ~/code/api/CLAUDE.md · 49k tokens per request Claude Code docs

  • Keep CLAUDE.md short

    It rides along on every single request. Under 200 lines, only things Claude cannot work out from the repo. Long how-tos go in a skill, which loads only when used.

    target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence. Claude Code docs

  • Point at the file

    “Improve this codebase” makes it read everything. Name the function and the file and it reads one thing.

    Specific requests like "add input validation to the login function in auth.ts" let Claude work efficiently with minimal file reads. Claude Code docs

  • Plan first, and give it a test to pass

    Shift+Tab into plan mode for anything non-trivial, so you catch a wrong approach before it is built. Then hand it a test or a screenshot so it can check its own work instead of you re-prompting.

    Claude explores the codebase and proposes an approach for your approval, preventing expensive re-work when the initial direction is wrong. Claude Code docs

  • Noisy job? Send a subagent. But do not overdo it.

    Test runs and log digging flood your main chat. A subagent does the reading and hands back a summary. It still spends tokens of its own, and a team of agents costs about seven times a normal session.

    the verbose output stays in the subagent's context while only a summary returns to your main conversation. · Agent teams use approximately 7x more tokens than standard sessions when teammates run in plan mode Claude Code docs

  • Use the CLI you already have

    gh, aws, gcloud cost nothing until used. Every connected MCP server adds a listing. Run /mcp and switch off the ones you are not using.

    Tools like gh, aws, gcloud, and sentry-cli are still more context-efficient than MCP servers because they don't add any per-tool listing. Claude Code docs

  • Quick side question? /btw

    It answers from what is already in the conversation and does not add the exchange to your history.

    Ask a side question about the current session without adding to the conversation. Claude Code docs

  • Leave effort on medium

    It is the default for a reason. For one hard turn, write ultrathink in the prompt instead of raising the whole session. And max is not “best”.

    may show diminishing returns and is prone to overthinking, so test before adopting it broadly. Claude Code docs

  • Kill loops you forgot about

    A /loop or scheduled task in an open session keeps firing while you are away, and each tick sends the whole conversation.

    a session-scoped scheduled task fires on its interval even while the session is idle, sending your full context each time Claude Code docs

Tricks from the people who build it

  • The “conclusion only” test

    Not sure whether to hand something to a subagent? Ask yourself one question. If you only need the answer, delegate. If you will need the raw output again, keep it in the main chat.

    will I need this tool output again, or just the conclusion? Thariq Shihipar, Anthropic, Apr 2026

  • Compact on your terms, with a focus

    Auto-compact fires when the window is fullest, which is exactly when Claude summarises worst. Do it yourself at a natural break and say what to keep: /compact focus on the auth refactor, drop the test debugging.

    due to context rot, the model is at its least intelligent point when compacting. Thariq Shihipar, Anthropic, Apr 2026

  • Wander off a lot? Cap the window

    Coming back to a huge stale session re-reads all of it at full price. A smaller window means a smaller bill for that mistake: /autocompact 400k.

    if you leave your computer for over an hour then continue a stale session, it's often a full cache miss. Boris Cherny, Claude Code team, Apr 2026

  • Plugin hoarding costs you

    Every installed skill adds its description to every turn, and plugins can start background agents. If usage looks odd, check /usage and prune what you do not use.

    People pulling in a large number of skills, or running many agents or background automations … This was the case for a surprisingly large number of users Boris Cherny, Apr 2026

  • Let it interview you, then build in a clean session

    For anything fuzzy: “Interview me until you could write the spec, then write it to SPEC.md.” Then start fresh and point at the file. The build session starts small and knows what done means.

    Once SPEC.md exists, start a fresh session to build from it, so the build begins with a clean context and a written definition of done. Claude Code docs

  • Turn the dial before you change the model

    Answer not good enough? Raise effort one notch first. Only move up a model if it had the context, tried, and still got it wrong. Pushing Sonnet to Max all day means you wanted Opus.

    try a higher effort first before moving up a model. Anthropic, 12 Nov 2026

  • Make your tests quiet and quick

    Claude reads every byte your test runner prints. Print failures only, put the reason on the same line as ERROR, and give it a fast mode that runs a sample.

    The test harness should not print thousands of useless bytes. Nicholas Carlini, Anthropic, Feb 2026

  • Get a second opinion from a fresh pair of eyes

    Asking the same chat “are you sure?” mostly gets you agreement. /code-review uses a reviewer that never saw the conversation.

    It isn't swayed by the reasoning that produced the code. Claude Code docs

Prompt caching

  • Turn it on first

    One top-level cache_control field. Prefix order is tools → system → messages; a change at any level invalidates it and everything after. Minimum prefix is 512 tokens on current models, and shorter prompts silently skip caching.

    Turn on prompt caching before any other lever. Cost guide · Caching docs

  • Keep the prefix byte-stable

    No timestamps, request IDs or unsorted JSON above the breakpoint. Put per-request text at the end of the newest user turn.

    a 25-token status line at the front of the system prompt made each request write the whole conversation Cost guide

  • Append, never edit

    New instruction mid-conversation? Append a {"role": "system"} message to messages instead of rewriting top-level system. Hold model, tools and top-level effort fixed for the session.

    Editing the system prompt cost about 25 to 50 times what the same text cost as a mid-conversation system message. Cost guide

  • Choose the TTL from your gaps

    5 minutes refreshes free on every hit, so it suits steady traffic. Use 1 hour once about 1 turn in 20 follows a 5–60 minute pause. Break-even is one read at 5 min, two reads at 1 h. Fanning out in parallel? Wait for the first response to start, or the others all miss.

    a cache entry only becomes available after the first response starts. Caching docs

  • Verify from usage, not from the code

    Cache reads also do not count toward your input-tokens-per-minute limit, so a high hit rate raises throughput too.

    agent loops read a median 84% of their input from the cache … Below about 80%, look for something breaking the cache Cost guide · Rate limits

const stream = client.messages.stream({
  model,                                  // fixed for the whole conversation
  max_tokens: 64000,                      // a backstop, not a budget
  cache_control: { type: "ephemeral" },   // automatic caching
  system: STABLE_SYSTEM,                  // no timestamps or IDs in here
  messages,                               // append-only
});
const { usage } = await stream.finalMessage();
// Healthy loop: cache_read_input_tokens far above input_tokens.
console.log(usage.input_tokens, usage.cache_creation_input_tokens,
            usage.cache_read_input_tokens, usage.output_tokens);

Output, effort and thinking

  • Output is the expensive side

    Output costs 5× input on every current model, and in a loop each token written is re-read on every later turn. Specify the shape you will read. In Anthropic's test a one-line format cost $0.49 per run against $1.40 for a memo, at the same accuracy band.

    Ask for the answer you will read, not the one that looks thorough. Cost guide

  • Sweep effort before you change model

    Opus 5.5 on a SWE-bench Pro subset: low 87.4% at $0.11, medium 92.8% at $0.21, high 95.3% at $0.29, xhigh 96.7% at $0.74 per task. If outputs are checkable, run low and re-run only failures at high: about 97% for about $0.17.

    Tuning effort is often a better lever than switching models. Choosing a model · Effort docs

  • Thinking is billed output, even when hidden

    It cannot be disabled on Fable or Opus 5.5, and budget_tokens returns a 400 on current models. Effort is the control. Read spend from usage.output_tokens_details.thinking_tokens.

    the tokens Claude spends reasoning are billed as output tokens, even when the thinking text isn't returned to you Thinking docs

  • Set max_tokens to 64,000 and stream

    At 16,384, Fable 5.2 had 85% of attempts cut off and solved 20.3%, at $27.96 per solved task. At 64,000, 2% were cut off and it solved 77.4%, at $24.42. Treat stop_reason: "max_tokens" as a failure. A high cap has no rate-limit penalty.

    The turns that needed the room are discarded and still billed. Cost guide

  • Delete instructions written for older models

    “Verify twice”, “be maximally thorough”, ALL-CAPS emphasis. Prompts carried from Opus 4.8 to Opus 5 cost 36% more per ticket with no accuracy change until audited.

    A newer model follows such instructions to the letter, producing extra tool rounds and extra writing that you pay for with no gain in accuracy Cost guide

Tools, files and context

  • Defer tool definitions

    From about 10 tools or 10K tokens of schemas, add tool search with defer_loading: true and keep your 3–5 most-used tools loaded. It appends rather than swaps, so the cache survives.

    A typical multiserver setup (GitHub, Slack, Sentry, Grafana, and Splunk) can consume ~55k tokens in definitions before Claude does any work. Tool search typically reduces this by over 85 percent Tool search docs

  • Let code call the tools

    Programmatic tool calling keeps intermediate results out of context. It pays on chains and fan-outs, not on single sequential calls (there it cost about 8% more).

    improved performance by an average of 11 percent while using 24 percent fewer input tokens PTC docs

  • Make tool results small

    Paginate, filter, truncate. Offer a response_format of concise or detailed. Prefer get_policy(id) to get_all_policies().

    we use ~⅓ of the tokens with "concise" tool responses. Anthropic engineering

  • Upload data, do not paste it

    Files API plus code execution: the model queries the file in a sandbox and only the answer enters context.

    Pasted into the prompt, the table is about 91,000 input tokens on every request, and Claude Sonnet 5 answered 7 of 25 questions correctly. Uploaded, with code execution, it answered all 25, and the run cost about a twelfth as much. Cost guide

  • Downscale images, count PDF pages

    Image tokens = ⌈width / 28⌉ × ⌈height / 28⌉. A 1280×720 screenshot is about 1,200 tokens; a full-resolution one on a 4.7+ model can reach 4,784. PDFs run 1,500–3,000 tokens per page.

    downsample images before sending to control token costs. Vision docs · PDF docs

  • Compaction for long sessions only

    Server-side compaction saved 32% on a long run and nothing on a short one. Context editing is for making room, not saving money: it added 73% on the short run because every clear rewrites the cache. Do not prune history client-side on current models; it invalidates thinking blocks.

    The context levers only pay on a session long enough to need them Cost guide

  • One model before two

    An orchestrator with cheaper subagents cost about a third less only on work larger than one context window. Elsewhere, the same model at lower effort won.

    Start with the simplest approach that works, and add complexity only when evidence supports it. Anthropic, Jan 2026 · Cost guide

Picking a model

  • Default to Opus 5.5 at medium

    Try Haiku 5.5 first for high-volume work with checkable outputs. Reach for Fable 5.2 when evals on Opus 5.5 at higher effort still fall short.

    For most agent workloads, start with Claude Opus 5.5 at its default effort (medium). Cost guide

  • Watch the Haiku 100K step

    Past 100,000 prompt tokens every token of the request costs 5×, cached tokens included in the count. A compaction trigger of 90,000 cost 70% less per request than the 150,000 default.

    Past that, every token of the request costs 5 times as much, output included. Cost guide

  • Re-count after a model change

    Models from 4.7 on use a tokenizer that yields about 30% more tokens for the same text. count_tokens is free; call it with the target model's ID.

    This tokenizer produces approximately 30% more tokens for the same text. Pricing · Token counting

  • Batch anything nobody is waiting on

    50% off input and output, stacks with caching (hits are best-effort, so use the 1-hour TTL for shared context). Up to 100,000 requests or 256 MB per batch.

    most batches finishing in less than 1 hour while reducing costs by 50 percent Batch docs

Claude Code, scripted

  • Cap headless runs

    claude -p "…" --max-turns 10 --max-budget-usd 2 for CI and scripts. --bare skips hooks, skills, plugins, MCP servers and CLAUDE.md when you want the leanest possible run.

    claude -p "prompt" runs once and exits, which is how Claude Code ends up in CI jobs, git hooks, and shell loops. Claude Code docs

  • Filter output with a hook

    A PreToolUse hook can rewrite a test command to pipe through tail -n 100 before Claude ever sees the output. The docs ship a ready-made script.

    a hook can grep for ERROR and return only matching lines, reducing context from tens of thousands of tokens to hundreds. Claude Code docs

  • Put subagents on a cheaper model

    Set model: haiku in a subagent's frontmatter. Defining your own agent named Explore overrides the built-in, so exploration can run on Haiku too.

    For simple subagent tasks, specify model: haiku in your subagent configuration. Claude Code docs

  • On an API key, set the cache to one hour

    Subscriptions get a 1-hour cache for the main conversation; API keys and cloud providers get 5 minutes. If you pause between turns, set "promptCacheTtl": "1h" in settings (v2.1.242+).

    Claude Code docs: which TTL each request gets

  • Install a code intelligence plugin

    For typed languages, language-server navigation replaces search-and-read loops.

    A single "go to definition" call replaces what might otherwise be a grep followed by reading multiple candidate files. Claude Code docs

  • Know the baseline

    Put context_window.used_percentage, cost.total_cost_usd and prompt_cache in your status line and compare against the fleet average.

    the average cost is around $13 per developer per active day and $150-250 per developer per month, with costs remaining below $30 per active day for 90% of users. Claude Code docs

Skip these

Popular advice that the evidence does not support

  • Set a low max_tokens to save money. The model cannot see the cap; cut-off answers are billed and thrown away. lowering it does not make the model economize. Cost guide
  • Max effort gives the best result. On Opus 5.5, xhigh scored 1.4 points above high for 2.5× the cost per task ($0.74 vs $0.29). Cost guide
  • The cheapest model per token is the cheapest to use. Count cost per finished task. Upgrading Sonnet 5 to 5.5 cost 87% less per solved coding task. Compare models on cost per completed task, not per token Cost guide
  • More agents means better answers. They cost several times more, and delegating is not the same as improving. multi-agent implementations typically use 3-10x more tokens than single-agent approaches for equivalent tasks Anthropic, Jan 2026 · Handing the same task to a subagent doesn't make the answer any better. Claude Code docs
  • A bigger context window means I can stop managing context. Quality drops as the window fills, and you pay to re-read all of it. As token count grows, accuracy and recall degrade, a phenomenon known as context rot. API docs
  • Tell Claude in the prompt to think less. Use the effort setting. Asking Claude Sonnet 5.5 in the system prompt to think less doesn't reliably reduce its thinking. API docs
  • Add a .claudeignore to hide files. Claude Code ignores it. Use Read(./secrets/**) deny rules. If your project has a .claudeignore file, it has no effect Claude Code docs
  • Split CLAUDE.md into @imports to make it cheaper. Imports load with the file that imports them. don't reduce its context cost Claude Code docs
  • Keep “double-check your work”, “be thorough” and “don't be lazy” in every prompt. Current models obey literally and do extra rounds. Removing “verify twice” cut cost per ticket by a third in Anthropic's test, with no accuracy loss. lines like that are more likely to cause over-work than fix a stall. Claude Code docs, Cost guide
  • Write “think hard” or “think harder” to get more reasoning. Those are plain text now. Only ultrathink is a keyword, and only in Claude Code. Everywhere else, use the effort setting. passes other phrases such as "think", "think hard", and "think more" through as ordinary prompt text Claude Code docs
  • Put IMPORTANT and YOU MUST in capitals so Claude listens. Say it plainly. For a rule that cannot bend, use a hook or a deny rule. piling on emphasis mostly makes Claude over-apply the rule. Claude Code docs
  • Make Claude talk like a caveman to save 65% of tokens. “Answer concisely.” does nearly all of it. The most popular such skill's own benchmark: 6,983 output tokens with no instruction, 4,334 with “Answer concisely.”, 4,119 with the skill, and the skill adds about 1,160 input tokens. "Be concise" is the real baseline; new models already know it. caveman README
  • Switch to a cheaper model halfway through for the easy parts. The switch re-reads your whole history at full price. Use a subagent on Haiku, or a new session. Claude Code docs
  • MCP servers always flood your context. True in 2025, outdated in Claude Code now. A plain CLI is still leaner. MCP tool definitions are deferred by default, so only tool names and server instructions enter context until Claude uses a specific tool. Claude Code docs
  • Saying please and thank you burns your limit. No measurement found on any official page. A few words are noise next to the conversation being re-read. a one-line question in a session that has been open all day still draws usage for the whole conversation. Claude Code docs
